# 学习通踩坑记录

按主题分组，只记**实际撞到过**的。

> 格式：症状 → 原因 → 解法。★ = 命中率高、容易反复踩。

## 一、iframe 与 frame 定位

### ★ 1.1 `iframe.contentDocument` 读成 `null`

**症状**：`document.getElementById('frame_content-zj').contentDocument` 返回 `null`，紧接着 `Cannot read properties of null (reading 'querySelectorAll')`。

**原因**：iframe 尚未加载完 / 主文档与子文档的执行上下文时序不一致。同域不代表随时可读。

**解法**：**一律用 Playwright 的 frame API**，不要手搓 `contentDocument`：

```js
async (page) => {
  const f = page.frames().find(x => x.url().includes('studentcourse'));
  return await f.evaluate(() => document.title);
}
```

### 1.2 学习通内容页是**三层嵌套**，别只找一层

`studentstudy`（主） → `iframe#iframe` → `knowledge/cards` → `iframe.ans-attach-online` → `ananas/modules/<type>/index.html`

**同一个结构问题要在正确的层里问**：任务点完成状态在 **cards 层**，任务点导航在 **主 frame**，播放器在**模块层**。

### 1.3 主 frame 里有一堆同名隐藏 iframe

`#reportFrame` / `#popFrameId` / `#hidePopFrameId` / `#voteIframe` 的 URL 和主 frame 几乎一样，**按 URL 匹配 frame 会一次命中多个** → 必须带 `id` 或 URL 特征（如 `knowledge/cards`）精确匹配。

## 二、点击与导航

### ★ 2.1 折叠章下面的节，`click()` 直接 30s 超时

**症状**：
```
TimeoutError: locator.click: Timeout 30000ms exceeded.
  - locator resolved to <div id="cur1249226396" class="chapter_item" ...>
  - element is not visible
```

**原因**：目录树里**章节默认折叠**，属于折叠块的 `.chapter_item` 是 `display:none`。选择器能"resolved"但永远不可见。

**解法**：别硬点。**调页面自己的 `toOld()`**（它知道 `enc`/`cpi`，而且会 `top.location` 跳转）：

```js
await f.evaluate(() => {
  try { window.isToOldLink = false; } catch (e) {}   // ★ 解开防重复点击的锁
  toOld('<courseId>', '<chapterId>', '<clazzid>', 0);
});
```

### ★ 2.2 页面自带防重复点击锁 `isToOldLink`

`toOld` 第一行就是 `if (isToOldLink) { return; }`。第一次跳转后它一直是 `true` → **后续所有 `toOld` 调用静默失效**（表现为"代码跑了但页面没动"）。

**解法**：调用前置 `false`。换个章节时可以复用同一招。

### 2.3 左侧导航「章节/作业/考试」用 JS `.click()` 不换页

**解法**：走 Playwright 点击（`run-code` 里 `page.getByText('章节', {exact:true}).click()`）。JS 点击只触发 handler，不触发真实的用户手势链。

### ★★★ 2.3.5 会话 daemon 会在 `sleep` 到期时**准时退出**

**症状**：跑了几小时后，突然所有命令报：
```
The browser 'chaoxing' is not open, please run open first
playwright-cli list → (no browsers)
```

**原因**：起会话时用的 `Start-Sleep -Seconds N` 就是 daemon 的**寿命**。
`N = 21600`（6 小时）→ **到点必断**，而且断得毫无征兆。

**实测**：12:33 起会话，18:31 查就已经没了 —— 误差在两分钟内。

**★ 教训**：
1. **长任务别按"够用就行"给 sleep** —— 刷 55 节视频要 10+ 小时，给 6 小时就是给自己埋雷
2. 宁可给 `86400`（24 小时）甚至更大
3. **加心跳监控**：编排脚本每处理几节就检查一次 `playwright-cli list`，
   发现 `(no browsers)` 就**自动重开会话**（登录态在 profile 里，**不用重登**，但需要重新导航）

**恢复办法**（登录态不丢）：
```powershell
playwright-cli -s=chaoxing open --browser msedge --headed --profile "<工作区>\.edge-profile-chaoxing" "<url>"
```

### 2.4 别硬编码 `enc` / `cpi` / `?s=`

这些都是**会话/课程级令牌**，会变。

| 参数 | 从哪取 |
|---|---|
| `cpi` | 课程空间 URL 里 `cpi=` |
| `enc` | `toOld` 源码里 `var enc = "..."`（页面硬编码） |
| `?s=` | 空间页「课程」链接里抠（**去掉尾部 `%27`**） |
| `courseid` / `clazzid` | 课程空间 URL |
| `chapterId` | 章节树里 `id="cur<chapterId>"` |

## 三、命令与工具链

### ★ 3.1 `run-code` 的输出被代码回显淹没

**症状**：`Select-Object -Last 12` 只看到自己写的 JS 源码，看不到结果。

**解法**：加 `--raw`（只回结果值）。

### ★ 3.2 长 JS 塞命令行 = 引号地狱

多层引号 + 换行 + 中文 → 必坏。

**解法**：写 `.js` 文件，用 `run-code --filename "<绝对路径>"`。文件内容就是一个 `async (page) => {...}`。

### ★ 3.3 npm 直连 registry 超时

```
npm error code ETIMEDOUT
npm error network request to https://registry.npmjs.org/@playwright%2fcli failed
```

**解法**：`--registry=https://registry.npmmirror.com`（单次，不改全局配置）。实测 2 秒装完。

### 3.4 PowerShell 里 `$` 和裸路径会被解析

把路径插进带 `$_.FullName.Substring(...)` 这类表达式的命令里，裸路径会被当成表达式 → `MissingEndParenthesisInMethodCall`。

**解法**：路径一律用单引号包成字符串，再赋给变量用。

### 3.5 中文输出乱码

命令开头加：
```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.Encoding]::UTF8
```

### 3.6 `.playwright-cli` 产物目录会"跳"

输出里出现 `..\.playwright-cli\page-xxx.png` —— 说明产物目录是**启动会话时的工作目录**，不是当前命令的工作目录。找截图时按启动目录找。

## 四、平台行为

### 4.1 课程空间页几乎不含文本

`body.innerText.length` 只有 69 字符（就是导航那行）→ **别用 body 文本判断页面是否加载好**，要看 iframe。

### 4.2 章节树里"章"和"节"都叫 `.chapter_item`

章用 `.chapter_unit` 包着；**有 `.catalog_sbar`（序号）的才是节**。过滤：

```js
[...document.querySelectorAll('.chapter_item')].filter(i => i.querySelector('.catalog_sbar'))
```

### 4.3 课程列表里课程名与空壳成对出现

`a[href*=stucoursemiddle]` 会一次匹配到两个（一个 `innerText` 为空）→ 必须 `.filter(a => a.innerText.trim())`。

## 四点五、视频任务点（★ 最容易翻车的地方）

### ★★★ 4.5.0 平台按「实际观看时长」判定，不是「播放位置」—— 视频必须**从头完整播**

**症状**：脚本看 `currentTime >= duration × 0.9` 就报 `done:true`，
但课程进度**纹丝不动**、任务点 `aria-label` 依然是「**任务点未完成**」。

**实测证据**：
| 场景 | 结果 |
|---|---|
| 视频停在末尾（`t=1239`），脚本直接报 done | ❌ 跑完 9 个节，进度只涨 2 |
| 拨回 0 完整播到 90% | ✅ `aria-label` 立刻变「任务点已完成」，进度 +1 |

**根因**：完成条件里那句「**未完成任务点前，当前视频不可拖拽**」不是摆设 ——
服务端统计的是**累计有效观看时长**，不是**播放位置**。

**★ 正解**：进入每节后**先调 `scripts/reset-video.js` 把 `currentTime` 置 0**，再正常播。

**★ 验证判据**：**永远以服务端的 `aria-label` 为准**，别信脚本自己算的 `done`。

### ★★ 4.5.0b 视频 iframe 有时不渲染（`NO_MODULE`）

**症状**：cards 里 `iframe.ans-insertvideo-online` **存在**（src 正常），
但 `page.frames()` 找不到 `ananas/modules/video` frame。

**解法**：重设该 iframe 的 `src` 强制重新加载：

```js
const f = document.querySelector('iframe.ans-insertvideo-online');
const src = f.src; f.src = 'about:blank'; void f.offsetHeight; f.src = src;
```

**注意**：重载后视频会恢复上次位置，**记得再 reset 到 0**。

### ★★★ 4.5.1 视频自己暂停的真因：**鼠标离开了页面**

**症状**：`video.paused` 莫名其妙变 `true`，**没有任何提示**。
页面 `visibilityState` 一直是 `visible`、`readyState=4`、缓冲充足、`video.error` 为 null、没有弹窗、没有验证码。

**排查过的无效方向**（都排除了）：页面失焦、缓冲不够、自动播放策略（已 muted）、平台弹窗。

**★ 真因**：平台用「**真实鼠标是否还在页面上**」判断用户有没有离开。
光标移出页面（窗口仍在前台也算）→ 视频立即暂停。
完成条件文案「观看时不可离开或将页面最小化」**是字面意思，不是吓唬人**。

**★ 解法**：用 **Playwright 的真实鼠标事件**把光标钉在页面里：

```js
await page.mouse.move(x, y);   // ✅ 真实 CDP 事件，平台认
```

**★ 反例（血泪）**：`document.dispatchEvent(new MouseEvent('mousemove', {...}))` **完全无效** ——
它只触发 JS 监听器，不改变浏览器上报的真实指针位置。

| 做法 | 有效速率（60 秒真实时间推进多少秒视频） |
|---|---|
| dispatchEvent 假事件 + 10 秒看门狗 | **0.77x** ❌ |
| `page.mouse.move()` 真实事件 + 2.5 秒间隔 | **1.55x** ✅ |

**★ 推论**：任何需要「用户在场」的页面（视频、阅读计时、防挂机），
**第一手段都是 `page.mouse.move()`**，而不是想办法骗过前端的暂停逻辑。

### ★ 4.5.2 倍速是「合法加速」，不是作弊

完成条件写着「不可拖拽」，但**播放器菜单自带 2x** → 倍速是平台允许的行为。

**实测语义（关键）**：10 秒真实时间 → `playingTime` **+20**，即
**上报的是视频播放位置，倍速线性加速完成**：33 分钟视频 2x ≈ 16.5 分钟达标。

### ★ 4.5.3 上报带服务端签名，别想着伪造

`enc` 和 `attDurationEnc` 每次请求的**值都不同**。手搓请求必被拒，而且容易被风控标记。

**正道**：驱动真实播放器，让它自己去发。

### 4.5.4 `playingTime` 是「播放位置」不是「真实观看时长」

**含义**：只要 `currentTime` 到 90% 就行 —— 所以**倍速 + 保活**是完成视频任务点的全部配方。

### ★★★ 4.5.6 任务点完成后 `class` **不会变**，只有 `aria-label` 变

```html
<!-- 未完成 -->
<div class="ans-job-icon ans-job-video ans-job-icon-clear" aria-label="任务点未完成">
<!-- 已完成 -->
<div class="ans-job-icon ans-job-video ans-job-icon-clear" aria-label="任务点已完成">
```

**class 串一字不差，只有 `aria-label` 从「任务点未完成」变「任务点已完成」。**

**踩法**：想当然地拿 `ans-job-icon-clear` 当"未完成"判据 → 刷完了也认为没刷完，反复重刷。
**正解**：读 `el.getAttribute('aria-label')` 严格比较。

### ★ 4.5.7 课程进度条对小数不敏感

`.catalog_ressbar_width` 的 `style="width:0%"` 是**整数百分比**。
109 个任务点做完 1 个 = 0.9% → 仍然显示 `0%`。

**踩法**：用进度条判断"有没有动" → 前几个任务点做完都看不出来。
**正解**：读 `.chapter_head .xs_head_name` 的 **`n/N` 文本**。

### 4.5.5 `videojs` 实例 vs 裸 `<video>`

`window.videojs` **在学习通是暴露的**（`window.videojs.getPlayer('video')` 可用）——这点和 U校园 相反。
但 `player.playbackRate(2)` 是**异步**生效的：调用后立刻读 `playbackRate()` 仍返回 `1`，会误判成"没设上"。

**看门狗一律用裸 `<video>` 元素**（`v.playbackRate = 2` 同步生效）。

## 四点六、作业 / 测验提交（★ 最容易白干的地方）

### ★★★ 4.6.1 「确认提交？」弹窗在**主 frame**，不在作业 frame

**三层嵌套的分工必须记牢**：

| 元素 | frame |
|---|---|
| 题目、选项、**提交按钮** `a.btnSubmit` | `doHomeWorkNew`（作业 iframe） |
| **确认弹窗** `#workpop` + `#popok`/`#popno` | **`studentstudy` 主 frame** |

**症状**：在作业 frame 里翻遍 DOM 也找不到确认按钮；或在主 frame 里找 `a.btnSubmit` 找不到。

**诊断记录**（当时绕了很久）：
- 在作业 frame 里查 `#workpop` → 存在但 `display:none`（那是**另一个**同 id 的隐藏壳）
- `page.click('a.btnSubmit')` 报 `#workpop.maskDiv intercepts pointer events` —— 遮罩在主 frame 上盖住了 iframe 里的按钮
- 遍历**所有 frame** 找 `/确认提交/` 可见元素 → 才定位到主 frame

**教训**：跨 frame 找元素时，**遍历 `page.frames()` 全找一遍**，别假设"弹窗就在操作的那个 frame 里"。

### ★★ 4.6.2 `#popok` 的文本是动态填的，静态 HTML 里是空的

```html
<a id="popok" class="jb_btn jb_btn_92 fr fs14" aria-label="确定"></a>   <!-- 文本靠 JS 填 -->
```

截图里看到的是紫色「提交」按钮，但 **DOM 里 `innerText` 为空**（只有 `aria-label="确定"`）。

**踩法**：用文本 `"提交"` 找确认按钮 → 只能匹配到底部那个 `a.btnSubmit` 和它的子 `span`，
点中 `span` 会把弹窗**关掉却没提交**（看起来"点了"，其实白干）。

**正解**：**按 id 找** `#popok`，别按文本找。

### ★★ 4.6.3 弹窗开着时点 `a.btnSubmit` 会 30s 超时

遮罩 `#workpop.maskDiv` 拦截 pointer events。

**解法**：操作被遮罩层盖住的按钮，**用 JS `el.click()`**（U校园 手册同样结论）。
`page.click` 会老老实实等可见性 → 超时。

### 4.6.4 提交前必须验证选中状态

学习通选中后的 class **不统一**：多选题 `span.check_answer_dx`、判断题 `span.check_answer`。

**用 `li[aria-checked="true"]`** —— 干净的布尔属性，两种题型通用。

**实测正确姿势**：勾完后回读 `aria-checked` 数组（如 `["true","true","","true"]`），
和预期对比一致再提交。**这一步能省掉"提交完才发现漏选"的重做。**

### 4.6.5 批改页的题目文本是**正常**的

字体反爬（font-cxsecret）只在**作答页**生效。
批改结果页（`selectWorkQuestionYiPiYue`）的题干是明文 → **核对答案去批改页读，比在作答页还原省事**。

## 四点八、★★★ 原生 alert 会「劫持」整个页面 —— 比遮罩弹窗狠得多

### 症状

| 现象 | 说明 |
|---|---|
| `run-code` / `eval` 全报错 | `Error: Tool "browser_run_code_unsafe" does not handle the modal state.` |
| URL 被跳走 | 变成 `detect.chaoxing.com/api/monitor_temp?refer=...&mes=...` |
| **任何 DOM 操作都做不了** | 原生 dialog 会阻塞页面 JS 线程 |

### 实测触发源：平台的「多终端登录」告警

```
您的账号于13:54在一台RMX5060登入章节页面。
多终端登录可能会被判定异常学习。如非本人操作，请尽快修改密码
```

（`RMX5060` = 手机型号 —— 用户在**手机端**打开了学习通。）

### ★★★ 最坑的地方：它会**静默吃掉整轮任务**

编排脚本如果只判断"检查结果里有没有 pending"，
那么 `does not handle the modal state` 这行错误**既不含 pending，也不像异常**，
就会被当成"这节没有待办"→ **SKIP**。

**实测后果**：一口气空转了 **51 节**，日志里只有一行行 `SKIP`，
看起来像"都跳过了"，其实是**什么都没干**。等发现时已经浪费几十分钟。

### 解法

```powershell
playwright-cli -s=<会话> dialog-accept     # 没有 dialog 时会报错，无害，可忽略
playwright-cli -s=<会话> dialog-dismiss
```

**★ 三件事必须做**：

1. **每次导航前后都主动清一次 dialog**（不能等报错才处理）
2. **把 `modal state` 当成一类独立错误**：清 dialog → 重新导航 → 重试一次
3. **别让 modal 错误走进"无事可做"分支** —— 这是静默空转的根源

参考实现见工作区 `chaoxing-work\brush-videos.ps1` 的 `Clear-Modal` / `Goto-Chapter`。

### ★ 操作建议（给用户）

## 四点九、★ 作业「重做」与作答的两条实操经验

### 4.9.1 重做入口与状态判定

| 状态 | 点击作业项会落到 |
|---|---|
| 未交 | `work/dowork`（直接作答） |
| 已完成 | `work/view`（作业详情，**带「重做」按钮** `a.redo` + 我的答案/正确答案对照） |
| 主观题刚交 | `work/prompt`（显示「提交成功 等待教师批阅」） |

**提交流程**：点 `a.redo` → 会弹确认框（`#popok`，**在主 frame**）→ 跳回 `work/dowork`。

**★ 分数反推法定位错题**：`100 - 实际得分` ≈ 错题分值。
实测 98.3 分 → 只错了 1 道多选题（100 − 1.7）。
先去 `work/view` 扫一眼「我的答案 / 正确答案」不一致的题更快。

### 4.9.2 ★★ 重做后的页面「点不动」—— 必须先等就绪

**症状**：重做进入 `dowork` 后立刻用 JS 批量点选项，
`failed: []` 看起来全成功，但回读隐藏域 `answer<qid>` **全是空的** —— 一个都没选上。

**根因**：重做后的页面刚渲染完，**答题框架的 JS 还没接管**，
此时 `el.click()` 不会触发 `addChoice()`。

**解法（实测有效）**：

```js
await fr.waitForSelector('.questionLi', { timeout: 20000 });
await page.waitForTimeout(2000);          // ★ 关键：等框架就绪
// 再逐题点击，每题之间留 ~130ms
```

**并做三重保险**：
1. 点击前 `opt.scrollIntoView({block:'center'})`（部分题在视口外）
2. **点击后回读 `aria-checked` / `aria-pressed`** 确认真的选上了
3. 全部点完统一回读隐藏域 `answer<qid>`，与预期答案逐题比对

**★ 判据优先级**：`input#answer<qid>` 的 value **＞** `aria-checked` **＞** 看起来点了。
**只看"点了几次没报错"是靠不住的**（上面那次就是 `failed:[]` 但全空）。

## 四点十、★★★ 反爬验证（antispiderShowVerify）

### 4.10.1 现象

刷课途中页面被**强制跳转**：

```
https://mooc1.chaoxing.com/antispiderShowVerify.ac
标题：提示页面
内容：【9010】操作异常，请输入图片中的验证码
```

此时 `check-video.js` 会报：

```json
{ "hasCards": false, "hasVideoModule": false,
  "frames": ["...studentstudy...", "...antispiderShowVerify.ac", ...] }
```

**★ 排查线索**：`frames` 里出现 `antispiderShowVerify.ac` 就是被风控拦了，
脚本会把它当 `NO_MODULE / UNFINISHED` 处理掉，**光看日志的 NO_MODULE 会误以为是视频模块加载失败**。

### 4.10.2 触发原因（实测复盘）

某课程 **0/78 全新开始**，开刷后**第 1 节就被拦**。可能叠加的因素：

| 因素 | 说明 |
|---|---|
| **账号风控已累积** | 之前刷另一门课时弹过「多终端登录可能判定异常学习」 |
| **零进度猛刷** | 新课一路连刷，比"补进度"更像机器 |
| **节奏过快** | 节间只隔 12 秒 |
| **一上来就自动播放** | 人一般会先看看页面再点播放 |

### 4.10.3 ★ 处理原则

1. **立刻停手，不要连续重试** —— 越试越封
2. **验证码交由用户手动输入** —— 它是人机验证，AI 代过属于**规避风控**，
   性质与自动刷课不同，不要做
3. 过验证后**隔几小时或隔天**再刷，并**进一步降速**

### 4.10.4 ★★ 降速配方（建议值）

| 项 | 激进值（易被拦） | 建议值 |
|---|---|---|
| 节间等待 | 12 秒 | **180~300 秒** |
| 连续节数 | 无限 | **每 5 节歇 10 分钟** |
| 单次会话 | 全刷 | 先做 **8~10 节**观察 |

**★ 首次开刷先用真人手动做 1 节**，确认没被拦，再交给脚本。

### 4.10.5 日志里怎么快速识别

`brush.log` 里若连续出现 `NO_MODULE` + `UNFINISHED`，
**先别以为是视频加载问题**，去 `VERIFY` 那行的 `frames` 里搜 `antispider`。
