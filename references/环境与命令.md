# 环境与命令（Windows / PowerShell）

> U校园 那份手册是 bash 风格（`&&` 串联、`sleep`、`curl`、`grep`）。
> **本机是 Windows + PowerShell，命令要换写法** —— 这份就是对照表。

## 1. 安装 playwright-cli

```powershell
npm install -g @playwright/cli --registry=https://registry.npmmirror.com
```

- 包名 **`@playwright/cli`**（微软官方 agent CLI），装完命令名是 `playwright-cli`
- **`registry.npmjs.org` 直连会 ETIMEDOUT** → 必须带镜像
- 用 `--registry` **单次指定**，不动全局 npm 配置

验证：

```powershell
playwright-cli --version        # 实测 0.1.22
playwright-cli --help
```

## 2. 起会话（Edge + persistent profile）

```powershell
playwright-cli -s=<会话名> kill-all
Start-Sleep -Seconds 2
playwright-cli -s=<会话名> open --browser msedge --headed --profile "<工作区>\.edge-profile-<会话名>" "<URL>"
```

| 参数 | 说明 |
|---|---|
| `--browser msedge` | 本机只有 Edge（有 `msedge.exe`，无 Chrome） |
| `--headed` | 有头模式，登录/人工接管都需要 |
| `--profile <dir>` | **persistent profile，登录态存这里**，跨调用保持 |
| `--idle-timeout` | headed 模式默认**永不**超时，不用特意设 |

两个会话**不能共用同一 profile**（浏览器 user-data-dir 锁）。

## 3. ★ 后台常驻：DSH 里用后台 job

U校园 手册靠 `bash ... && sleep 21600` 钉住 shell —— Windows 下改成 **PowerShell + `Start-Sleep`**，并且**必须用工具的后台运行能力**（DSH：`run_in_background: true`），否则 shell 一结束 daemon 就死。

```powershell
# 一次性后台 job：开浏览器 + 钉住 6 小时
playwright-cli -s=<会话名> kill-all
Start-Sleep -Seconds 2
playwright-cli -s=<会话名> open --browser msedge --headed --profile "<dir>" "<url>"
Start-Sleep -Seconds 21600
```

**实测结论（✅）**：这样起出来的会话，**后续从别的 pwsh 进程调用 `-s=<会话名>` 完全可用** —— daemon 独立于启动它的 shell，只要那个后台 job 还活着。

后续所有命令**不需要**再跟长 sleep，直接调：

```powershell
playwright-cli -s=<会话名> tab-list
playwright-cli -s=<会话名> --raw eval "() => location.href"
playwright-cli -s=<会话名> screenshot
```

## 4. bash → PowerShell 对照

| 用途 | bash（U校园 手册） | PowerShell |
|---|---|---|
| 串联 | `a && b` | `a; b`（用 `;`，失败不自动中断） |
| 等待 | `sleep 3` | `Start-Sleep -Seconds 3` |
| 取末几行 | `\| tail -6` | `\| Select-Object -Last 6` |
| 取前几行 | `\| head -6` | `\| Select-Object -First 6` |
| 过滤 | `\| grep -E 'x'` | `\| Select-String -Pattern 'x'` |
| 下载 | `curl -s <u> -o f` | `Invoke-WebRequest -Uri <u> -OutFile f` |
| 环境变量 | `VAR=x cmd` | `$env:VAR='x'; cmd` |
| 复制目录 | `cp -r a b` | `Copy-Item -Recurse a b` |
| 列目录 | `ls -la` | `Get-ChildItem -Force` |

**中文输出乱码**时在命令开头加：

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.Encoding]::UTF8
```

## 4.5 ★ 后台循环判断 `done` 的转义坑

外层用 PowerShell 循环反复调看门狗时，**别写**：

```powershell
if ("$out" -match '"done":true') { break }    # ✗ 永远匹配不上
```

**原因**：`playwright-cli --raw` 的输出是**被 JSON 化过一次的字符串**，内层引号带反斜杠 ——
实际文本是 `{\"last\":{\"done\":true,…`，里面根本没有裸的 `"done":true`。

**改法**（任选）：

```powershell
if ("$out" -match 'done') { break }              # 宽松匹配
if ($out -join ' ' -like '*done*true*') { break }
```

**代价**：匹配不上不是"报错"，而是**静默空转到循环上限**（实测白跑 12 轮，每轮多花 2~3 秒启动开销）。

## 4.7 ★ PowerShell 里 `-s=$var` **不会展开变量**

```powershell
$S = 'chaoxing'
playwright-cli -s=$S goto "$url"     # ✗ 会话名被当成字面量 '$S'
# → The browser '$S' is not open, please run open first
```

**实测**：`-x=$var` 这种 `-`+短名+`=`+变量的 token，PowerShell 传给外部程序时**不做变量展开**。

**改法**（任选其一）：

```powershell
playwright-cli -s=chaoxing goto "$url"          # ✓ 直接写死
$SESS = "-s=$S"; playwright-cli $SESS goto "$url"   # ✓ 先拼好再传
```

**★ 连带经验**：写编排脚本前，**先单独跑一次那条命令**验证参数真的传对了 ——
否则脚本会"每次都失败得很快"，跑完 55 节才发现啥也没干。

## 4.8 ★ `pwsh` 不在 PATH，用 `powershell`

本机是 **Windows PowerShell 5.1**，没有 PowerShell 7：

```powershell
pwsh -File script.ps1            # ✗ CommandNotFoundException
powershell -NoProfile -ExecutionPolicy Bypass -File script.ps1   # ✓
```

**且 PS 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解码** → 脚本里的中文变乱码。
**编排脚本一律用 ASCII 输出**（判断逻辑靠 JSON 里的英文布尔字段，如 `pending:true`）。

## 5. ★ 传大段 JS：用文件，不要塞命令行

命令行传多行 JS 会被引号/换行转义搞坏（U校园 手册同样警告过）。

```powershell
playwright-cli -s=<会话名> run-code --filename "E:\path\probe.js"
```

`probe.js` 内容是一个 `async (page) => { ... }` 函数体，`return` 短字符串。

## 6. 输出体积纪律

| 招式 | 作用 |
|---|---|
| `--raw` | 只回结果值，**去掉代码回显**（不加的话结果会被大段代码淹没） |
| `eval` 里 `JSON.stringify` + `.slice(0, N)` | 卡死单次返回长度 |
| `\| Select-Object -Last N` | 只留尾部关键行 |
| 探测脚本分批 | 一次只问一个结构问题 |

## 7. 产物落盘位置

playwright-cli 把快照/截图/console 写到 **启动时会话时的工作目录** 下的 `.playwright-cli\`。
本手册实测时启动目录是工作区，所以产物在 `<工作区>\.playwright-cli\` —— **换目录调命令时注意相对路径会变**（输出里出现 `..\.playwright-cli\` 就是这个原因）。
